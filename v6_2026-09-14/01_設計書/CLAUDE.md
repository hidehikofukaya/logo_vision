# logo_vision

刻印マークをスマホ写真から検出し、**Bbox で特定してその部分のみ切り出す**プロジェクト。
+α として倍率・面内回転・法線傾きを推定する。

## 要件

### 出力
- `found`（未検出を返せる）、`bbox`（**方向付き矩形**）、切り出し画像
- +α: 倍率、面内回転角、法線の 3D 傾き

### 制約
| 項目 | 内容 |
|---|---|
| 速度 | **確率マップまで 50ms / 最終Bboxまで 150ms**（2026-09-13 に 100ms 一括から変更）|
| 精度 | **合格 = 刻印ブロックの画像軸 Bbox（教師）を 100% 覆い、かつ面積が教師の 2.0 倍未満**（2026-09-14 に 1.5 倍から緩和）。**損失の面積目標は 1.5 倍**（評価上限との間を余裕にする） |
| 評価の軸 | **個別の刻印が正しく認識できたか**が主。最終Bboxは決定論的に出してよい（指示 2026-09-12） |
| 教師 | **図面 1 枚/品番のみの few-shot が MUST**（→ §「few-shot の現状」） |
| 入力 | 静止画 1 枚 |
| 実写データ | **入手不可。**検証はデジタルツインで行う |
| 撮影側の施策 | **不可。**フラッシュ対撮影・斜光誘導・偏光フィルタはいずれも使えない |
| 被覆漏れ 0% の扱い | **(a) レンダ上で 0% と読み替える**（承認済み） |

### 対象（2ケースに集中）
| ケース | 内容 |
|---|---|
| **ロゴ × ガラス** | Honda H マーク 20mm + 英字行 + 丸囲み文字。白セラミック焼き付け。黒フリットのドット列が競合 |
| **文字 × 板金** | 大きめのアルファベット1文字 + `><` 囲みの材質コード 2〜7 行。絞り刻印 0.125〜0.175mm |
| **文字 × 吸音材** | `>PET<` 等の材料表示が再生繊維フェルトに**くぼむ形で**。**最悪条件**（`docs/05_` §11） |
| **文字 × 布タグ** | シートベルト帯の黒い織ラベルに白の印字・ロゴ。**易条件**（`docs/05_` §15） |

布印刷・樹脂刻印は一旦対象外（Stage 0 で測定済み、`docs/04_`）。

### 材質ごとの難しさ（可視度 = 刻印の輪郭の勾配 ÷ 背景の勾配）

| 材質 | 可視度 中央 | 備考 |
|---|---|---|
| ガラス | 3.51 | 競合率 0%。フリットのドット列だけが敵 |
| 板金 | 1.81 | 画角と手ブレが二重に効く。競合率 24.5% |
| **吸音材** | **1.55** | **背景の勾配95分位 197.5 がガラスの刻印 142.1 より強い。**指向光＋正対でのみ見える |
| 布タグ | 未測定 | **黒地に白でくっきり。易条件。**競合は帯の畝（1.6〜2.6mm）と縫い目 |

### 撮影条件
- **画角は「刻印部の法線」となす角で 45 度まで**（板の法線ではない。ガラス・板金共通）
- **吸音材だけは法線から 20 度以内、教師 Bbox が画面の 70〜90% を占める条件**（2026-09-14 緩和。`make_dataset.CASE_VIEW`）
- 板金は**表裏とも**撮る（→ §「裏返すと鏡像になる」）
- 手ブレ・部品が影になる・蛍光灯や電球が射す、を含む

## few-shot の現状（重要）

**認識系の設計は「図面 1 枚/品番」のまま。** ただし 3 点の注意がある。

### 1. 3 層の切り分けは維持されている

| レイヤ | 必要なデータ | 新品番の追加コスト |
|---|---|---|
| (a) 品番テンプレート | **図面 1 枚のみ** | 登録処理数秒。**学習なし** |
| (b) 汎用モデル（使うなら） | 複数品番の画像（一度きり） | 不要 |
| (c) マージン校正・閾値 | 画像 + 正解（一度きり） | 原則不要 |

デジタルツインは (b)(c) のデータ源になる。**(a) のコストは図面 1 枚のまま。**

### 2. デジタルツイン自身の入力は図面 1 枚ではない

合成データを作るために、実際には次を使っている。

| 入力 | 用途 |
|---|---|
| ロゴのラスタ画像 1 枚 | ガラスのロゴ（これは図面 1 枚に相当） |
| 文字列のリスト + TrueType フォント | 材質コード・英字行を生成 |
| 板の造形パラメータ（曲げ線・ビードの寸法） | 板金の形状 |
| 材質パラメータ（反射率・粗さ・異方性） | 見え方 |

**これは矛盾ではない。**デジタルツインは開発用の道具であって、実運用の入力ではない。

### 3. 【未対処】図面と実物の形状差を、まだ模擬していない

**現在、レンダされるマークの形状と、検出器に与えるテンプレートの形状が完全に一致している。**
実際には次のズレがある（`docs/02_` §4.2）。

- 図面の線幅は**作図上の約束**であって、実物の刻印の線幅とは一致しない
- 実物は角が丸まり、つぶれ、摩耗する
- 図面自体がインク的で品質が低い

**この差を入れないと、few-shot の頑健性を楽観的に評価してしまう。**
対処案: レンダ側のマーク形状に線幅変化・角丸め・わずかな非線形歪みを与え、
検出器には素の図面を渡す。**次の実装で入れるべき項目。**

## アーキテクチャ

### A. デジタルツイン（実装済み）

```
【入力】ロゴ画像 / 文字列 / 寸法 / 板の造形パラメータ
   │
   ├─ tools/prep_scene.py      ← cv2 が要るので Blender の外
   │    ・図面 → 高さマップ（距離変換 → smoothstep → 平滑）
   │    ・文字列 → TrueType でマスク生成
   │    ・板の造形（曲げ線・絞りビード）を行間に通す
   │    ・光沢ムラ（ヘアラインの筋 + 研磨むら）
   │    ・刻印部の面法線と中心を算出
   │    → npz: height / ink / frit / gloss / boxes / mark_normal / mark_center
   │
   ├─ blender/render_scene.py  ← Blender 5.2 + Cycles + OptiX
   │    ・高さマップを頂点に焼き込んで板を作る（真の変位）
   │    ・工場 HDRI（Poly Haven 6種）で照明。フラッシュなし
   │    ・遮蔽物（影）・直射光（蛍光灯 / 電球）をランダムに
   │    ・刻印法線まわり 45 度以内から立体角一様に視点を選ぶ
   │    ・カメラは刻印の中心を見る
   │    → リニア EXR + index.json（正解 H・マークごとの Bbox・条件）
   │
   ├─ tools/stage0_analyze.py : simulate_isp()
   │    手ブレ(光学) → 露出(中央重点) → ノイズ(センサ) → トーン → 8bit
   │
   └─ 評価
        tools/view_scene.py         現像 + 正解Bbox重ね描き
        tools/measure_visibility.py 可視度・競合率を条件別に
```

### B. 認識系（設計のみ、未実装）

詳細は `docs/02_` §3.2。要点のみ。

```
【登録時】品番ごと・図面1枚・数秒・学習なし
  図面 → 輪郭クリーニング → 系統判定 → 勾配方向テンプレート（回転×倍率）
                                     → 幾何記述子 → Bbox算出用の参照輪郭

【推論時】静止画1枚・100ms以内
  ① 前処理    照明正規化 → 極性不変の量子化勾配方向
  ② 候補抽出  品番非依存（古典の粗探索 or 汎用検出器）
  ③ 照合      候補 × テンプレート。0°/180°、および鏡像も試す
  ④ 精密化    輪郭ICP または 勾配上のECC
  ⑤ 検証      エッジ整合スコア + 共平面フュージョン
  ⑥ 出力      Bbox + 校正マージン、倍率、回転、傾き
```

## 測定結果（最新 = Stage 3、`docs/05_` §10.7）

指標は 2 つ。**可視度**（マーク輪郭の勾配 ÷ 背景の勾配。1.0 が「区別できない」）と
**競合率**（マーク輪郭より強い背景画素の割合。高いほど紛れやすい）。

| 区分 | 可視度 | 見えない率 | 競合率 |
|---|---|---|---|
| ガラス | 3.51× | 6% | **0.0%** |
| 板金 表 | 1.81× | 9% | **24.5%** |
| 板金 裏 | 1.71× | 16% | **26.2%** |

- 板金は**画角と手ブレが二重に効く**（可視度が下がり競合率が上がる）
  画角 0〜15度: 見えない率 0% / 競合 13.0% ↔ 30〜45度: 14% / 28.8%
- **板金の長辺 60px 未満は 40% が見えない。**要求解像度の下限
- ガラスは手ブレ 5.5px で競合率が 0% → 49.8% に急増
- **可視度が上がっても易しくなったとは読めない。**「見えるが紛れる」という別種の難しさ

## 認識系で実測したこと（docs/06）

- **速度は律速でない。**粗探索 1.94 G 回の uint8 加算 → NEON で 121 M 命令 → 1コアで 22〜60ms。
  公開実装からの外挿でも 17ms。**精度が律速**
- **閾値が緩いと照合器が盲目になる。**勾配の保持率 45% だと spread 後に全画素が全方向に反応し、
  応答マップが飽和（3.97/4）。**上位 3〜4% に絞る**
- **密なテクスチャに何でも吸い寄せられる。**全方向が密に存在する領域（フリット、ヘアライン、
  背景構造）では何を照合しても高得点。→ 局所平均応答で正規化する
- **検証ゲートが決め手。**spread しない素の勾配方向の一致度で、正解 0.942 対 偽 0.756 と分かれる。
  粗スコアがほぼ同じでも分離できる。`docs/02_` §5.2 の設計が実測で裏付けられた
- **CNN・ニューラルネットは一切使っていない。**import は cv2 と numpy のみ。学習済み重みゼロ。
  畳み込みは Sobel とガウシアンだけで、いずれも係数が決まった固定カーネル
- **【解決】倍率の系統的な過小評価の根本原因は「特徴点が独立な観測になっていなかった」こと。**
  spread 半径より狭い間隔の 2 点はほぼ同じ画素を見るので独立でない。小さいテンプレートほど
  密集して実効観測数が減り、密なエッジ領域なら何でも raw スコア 1.0 に飽和していた。
  → **特徴点の間隔を spread 直径以上に**し、独立点が 14 個未満の倍率を棄却。−59% → −25%
- **spread 半径は固定にしない。**被覆率が目標帯に入るよう自動調整する。固定だと解像度次第で飽和する
- **倍率は全マークで共有する。**同一平面・同一距離なので px/mm は物理的に同一
- **粗探索は 1 つに決めない。**スコアが飽和して同点になるため、同点圏を候補として残し、
  全解像度＋検証で決める。同点なら**大きい倍率を優先**（バイアスは常に小さい側に出る）
- **【構造的な弱点】量子化勾配方向は、点単位では倍率に不変。**
  「この画素のエッジの向きは45度」に倍率の情報は無く、倍率は特徴点の幾何配置にしか入らない。
  位置と角度が合うのに倍率だけ外すのはこの直接の帰結。**パラメータ調整では埋まらない**
- **倍率の探索範囲は広げてはいけない。**実測: ±12% で被覆30% / ±33% で 5% / 上方向+4段で 5%。
  候補を増やすと検出は増えるが被覆は落ちる（誤った倍率に票が流れる）
- **共有倍率は強力だが、外すと全マークが道連れ。**1枚まるごと 0/5 になる例が出た
- **試して悪化した案: 特徴点数をテンプレート寸法に比例させる**（検出率 47%→7%）。差し戻し済み

## 外堀を埋める方式の ROI 評価（docs/06 §15）

排除の結果を ROI として取り出し、**正解 Bbox を完全に含むか**を測った。`tools/moat.py`。

| 対象 | 窓 | 閾値 | 被覆率 | ROI面積 | 排除率 |
|---|---|---|---|---|---|
| **板金（情報量増し）** | 32 | 6% | **100.0%** | 59.8% | **40%** |
| ガラス（最良） | 48,96,192 | 6% | 94.5% | 69.8% | 30% |

- **発想は正しい。**必要条件なので安全で、板金では被覆率100%を実証
- **単独では不足。**排除できるのは無地と白飛びまで。絞り込みは30〜46%
- **ガラスで効かない理由**: 工場の構造が透けて板面のほぼ全体にエッジがある
- **フリットは排除できるコマがある**（窓48〜192pxに対しドットが細かく、窓平均が閾値に届かない）
- **足りないのは「構造がある」と「マークの構造がある」を分ける量。**現状はエッジの有無しか見ていない
- 照合の前段としては有効。既に `detect()` に組み込み済み

## 板金の構造を刻印に干渉させない（docs/06 §16）

**追加構造は刻印の外側だけ。行間を埋めるのは可。**マークのBbox内の板形状の高低差で検証。

| 版 | 中央 | 0.5mm超 |
|---|---|---|
| normal 修正前 → 後 | 0.23 → **0.03mm** | 30% → 14% |
| dense 修正前 → 後 | 0.61 → **0.07mm** | 65% → 33% |

3つの原因と対処:
- **構造の裾が隣の行に届く**（公称幅の約2倍まで広がる）→ 隙間を5〜9mmに広げ、幅を隙間の1/4以下に
- **マークを置く前に構造を配置していた** → **マークを先に置いて実Bboxを確定してから**構造を足す
- **大きい1文字が行の横で縦に全行をまたいでいた** → **行ブロックの上か下へ移動**

## 排除による絞り込み（docs/06 §12〜13、実測済み）

**似ているものを探すのでなく、明らかに違う領域を排除する**方式。必要条件なので正解を落とさない。

| 候補量 | 判定 | 実測 |
|---|---|---|
| **エッジ密度** | **採用** | 閾値8%で**正解の残存100% / ランダム窓の排除84%**。正解Bboxの密度は中央24.1%・最小10.4%、ランダム窓は中央0.9% |
| 方向エントロピー | **不採用** | マーク0.952 対 フリット0.952で**完全に同じ**。「フリットは等方」という仮説は誤り |
| 最大連結成分の占有率 | **不採用** | 中央値は3.9倍離れるが**裾が重なる**（マーク最小0.074 対 フリット最大0.214） |
| 説明率（テンプレート輪郭長÷窓エッジ数） | **不採用** | **逆相関。**正解0.254 対 誤検出0.338。重みに使うと覆えた30%→25%に悪化 |

- 排除ステージを入れても**精度は変わらない**（必要条件なので当然）。価値は探索空間84%削減による速度と誤検出機会の削減
- **フリット上の窓は密度10.8%で閾値8%を超えるため、フリット由来の誤検出は残る**
- 連結成分の面積はマーク224 対 フリット6 で**37倍**離れる。ソフトな重みなら余地があるが未検証

## 学習済み conv1 のチャンネル反応で領域を絞る（docs/06 §17、実測済み）

「テンプレートに強く反応するチャンネルと、まったく反応しないチャンネルの両方を使う」案を検証。
正解を1つも落とさない閾値での排除率:

| 使い方 | 排除率 |
|---|---|
| conv1 署名の余弦（素朴） | 40.9% |
| **conv1 の pos−neg（提案の形）** | **79.1%** |
| layer1（深い） | 8.5% |
| layer2（さらに深い） | 4.2% |
| **エッジ密度（既存）** | **84.2%** |
| pos−neg AND エッジ密度 | 85.5% |

- **「反応しないチャンネルも使う」が決定的**（40.9%→79.1%）。素朴な余弦では全領域が広く活性化して差が出ない
- **ただしエッジ密度とほぼ冗長。**密度で残った52領域のうち pos−neg が追加排除できるのは**7.7%**のみ
- **conv1 は実質「向きつきエッジ検出器」**なので、既に持っている情報と同じ。併用しても +1.3pt で割に合わない
- **深い層は逆に悪化**（8.5% / 4.2%）。§11 の「深い特徴は低テクスチャ・クロスモーダルで崩れる」を自前データで確認
- **必要なのは「マークの構造」と「それ以外の構造」を分ける特徴**で、ImageNet の汎用特徴にはそれが無い
- → §11 の推奨（合成の図面↔レンダのペアで品番非依存に一度だけ学習する小さなモダリティ変換）に戻る

## 未知のマークへの汎化（docs/06 §19、実測済み）

「学習させた後で似て非なる刻印が出てきたら対応できるのか」への回答。**学習なしで測れる。**

テンプレート105個を系統ごと**まるごと伏せ**、局所パッチが残りにどれだけ近いかを測った。
「既知並の割合」= 既知どうしの下位5%の水準に届いたパッチの割合。

| 受容野 | logo | letter | code | text | circled |
|---|---|---|---|---|---|
| 16px | 94.6% | 89.2% | 93.0% | 68.6% | **2.0%** |
| 24px | **100.0%** | 90.9% | 94.7% | 71.8% | **0.0%** |
| 32px | 100.0% | 98.2% | 46.2% | — | 0.0% |
| 48px | 88.9% | **22.5%** | — | — | — |

- **受容野を縛れば、マークは構造的に記憶できない。**見えるのは角・線端・平行線・曲率だけ
- **受容野を広げると崩れる**（code 32px 46%、letter 48px 22.5%）。**24px ≒ 4mm ≒ ストローク6本分が上限**
- **logo/letter/code はまるごと伏せても既知と同水準。**部品の水準では新しくない
- **circled だけ完全に外れる**（未知→既知 0.528 対 既知→既知 0.947）。その曲率半径の閉環が他に無い
- **手続き生成の乱雑グリフは logo/letter を実マークより良く覆う**（98.8% / 97.4%）が、
  **circled は覆えない**（2.8%）。寸法・線幅・インク率を合わせた版でも改善せず。
  **「込み具合が足りない」という仮説は外れ。網羅は自動では達成されない**
- **この測定は学習不要・実写不要・図面だけ・2分。**新品番の図面が来たら配備前に覆域を判定できる。
  **網羅は保証できないが、網羅していないことは検出できる**
- 近傍法は網の補間能力を無視するので判定は**保守側に外れる**（安全側）
- プール構成に偏りあり（code が78個）。**系統間の絶対比較には使えない**

### 学習系に拒否権を与えないこと（設計条件）

| 段 | 担当 |
|---|---|
| 候補生成 | 学習系 **+ 既存の古典探索を並列で** |
| スコア | 学習系（順位付けのみ） |
| **採否の最終判定** | **古典のまま。**学習重みを通さない |

これを守れば未知マークでの最悪ケースは「今日の性能」で、それ以下にはならない。

## 学習済みバックボーンについて（docs/06 §11、調査済み）

- **凍結 DINOv2 / ViT の差し替えは効かない。**「DINOv2 の特徴は textureless では有効な対応を作れない」
  と明言する論文あり。T-LESS の silhouette 0.02 対 HOPE 0.17。BOP 未知物体は最良 52.0 AP で 0.56 秒/枚
- **解像度の罠**: DINOv2 ViT-S/14 は stride 14。0.125mm の刻印ストロークはパッチより細い
- **図面→写真のギャップは凍結バックボーンでは埋まらない。**CNOS は非写実→写実レンダだけで +4.3 AP。
  二値線画のギャップはそれよりはるかに大きい。MINIMA も RGB-Sketch は「weak advantages」止まり
- **本件とほぼ同一設定の論文がある**（arXiv 2303.08438, CVM 2024）。二値マスク→工業グレースケール画像。
  **LINE-2D 14.7 対 提案手法 58.8（AUC@3px）で約4倍。**粗密2段で +12.9、エッジ変換モジュールで +1.2
- **推奨形**: ①小さなモダリティ変換+記述子CNN を既存の LUT 探索の前段に（deep-NCC / QATM の形）、
  ②上位候補の学習型検証・再順位付け（NOCTIS の cyclic thresholding は繰り返しテクスチャ対策で +3.4 AP。
  **本件のフリットのドット列そのもの**）。**探索ループに ViT は入れない**
- **コスト**: 3〜7M params、512px INT8 で 8〜20ms。残り 40〜70ms が既存探索に使える
- **few-shot は守れるが条件付き**: 品番非依存に合成ペアで一度だけ学習し、
  **品番テンプレートは実行時の入力のまま、重みにしない**こと。**これが最大のリスク**

## 【重要】裏返すとマークが鏡像になる

板を裏返すと座標が反転し凹凸の符号も反転するため、**マークは鏡像になる**。

- **「鏡映なら棄却」という健全性チェックは使えない**（`docs/01_` §6 に置いていた）
- 鏡像テンプレートが要る → テンプレート数が 2 倍
- **Honda ロゴの左右ミラー IoU は 0.899。**鏡像を許すと表裏がほぼ区別できない
- 表裏を分けるのは凹凸の符号だが、**極性不変な表現を意図的に採っているため、その情報を捨てている**
- **表裏の区別は不要と確認済み（2026-09-11）。**鏡像テンプレートを足すだけでよい

### 照明
- **同軸フラッシュ下では、刻印の平坦部は背景と区別できない。**見えるのは傾いた縁だけ。

- フラッシュ無しの現在、**板金は正対が最良**（Stage 0 のフラッシュ有り時とは逆）

## 実装上の落とし穴（再発防止）

| 症状 | 原因 | 対処 |
|---|---|---|
| ロールでマークが画角から外れる | ロールをオイラー角 Y に入れ、**光軸でなくワールド軸**まわりに回っていた | クォータニオンで光軸（ローカル Z）まわりに |
| 被写体が白飛び | 全体測光で明るい天井や鏡面に引きずられた | **中央重点測光** |
| 影やブレでコントラストが「上がる」 | 暗条件で自動露出がノイズを持ち上げ、**指標がノイズを測っていた** | `measure_visibility.py` の勾配比を使う。**素朴な輝度コントラストは使わない** |
| 全マークの可視度が 1.1 倍前後 | `os.path.basename` が**末尾スラッシュで空文字**を返し、別シーンのマスクを読んでいた | `d.rstrip("/\\")` してから basename |
| 光沢ムラが雲のよう | 等方ノイズを使っていた | **一方向に伸ばした筋（ヘアライン）を主成分に** |
| シーン構築が遅い | 頂点百万規模で `from_pydata` | `foreach_set` |
| 直射光で白飛び | 出力 [W] を直接振っていた | **部品面の照度を目標に、距離の二乗から出力を逆算**（E=P/4πd²） |
| 背景が無地の灰色 | 背景板が大きすぎて画面を覆う | 板の 1.9 倍に。環境が縁から見えるように |
| ガラスのコントラスト過大 | 明るい環境が透けていた | **暗い背景板**を背後に |
| 平らな面に高密度メッシュ | 変位の有無を見ていなかった | **変位が無ければメッシュは粗くてよい。**要るのはテクスチャ解像度 |
| **画角が距離クリップで潰れる** | **主カメラの最短撮影距離(85mm)で頭打ちになり、20mmの刻印が何を指定しても画面の17%止まり。3mm文字が7px** | **距離ではなくレンズで画角を決める**（高解像度からの切り出しと光学的に等価） |
| 軸平行の箱で面積を測ると読めない | **細長いマークで AABB は OBB の 2.6〜3.6倍**（全体2.39倍） | **方向付き矩形（OBB）で測る。**`group` 経路なら `minAreaRect` でほぼ無料 |
| アセットを名前で取ると別物が来る | バンドル内に**同名のプレビュー用カメラ**が同居 | **型（MESH）を確認してから取る** |
| 選択基準が面積を無視すると壊れる | 「余白+20%の被覆率」だけで選び、**面積16倍のモデルを最良と判定** | **K2w + 0.2xR**（個別マークの認識）で選ぶ |
| 箱の束ね処理が O(N²) | 種にする画素を絞っていない。**100ms予算に直結** | 上位600に制限（21ms/枚） |
| **見えないマークに正解箱が付く** | **遮蔽物がカメラと部品の間に入るのに、`visible` が画面内かどうかしか見ていなかった。マークの14.7%が該当** | 遮蔽物は視線から横へ退かす + **`mark_occlusion()` で光線を飛ばして実測**（`docs/07_` §4） |
| **壊れたまま「OK」が並ぶ** | **Blender は Python 例外でも終了コード 0 を返すことがある** | 戻り値でなく**成果物（index.json の件数）で成否を判定** |
| 高さ場が丸ごと NaN | 重み `exp(x/std)` が発散し inf/inf | 指数をクリップ。**自己検証に `np.isfinite` を追加** |
| 異方性にしたら構造が消えた | **同じ雑音**を複数方向に平均 → 等方に戻る | 方向ごとに**独立な雑音**、二乗和で正規化 |
| フェルトが「雲」になる | 等方ガウシアンのまだら | **繊維を1本ずつ** `polylines` で描く（実物は暗い地に明るい繊維が1本ずつ寝ている） |
| Blender で cv2 が無い | 同梱 Python に入っていない | cv2 が要る処理は `tools/` 側で事前に済ませる |
| Blender の出力がドライブ直下 | 相対パスの解決 | `os.path.abspath` |
| OpenCV が EXR を読まない | 既定で無効 | `OPENCV_IO_ENABLE_OPENEXR=1` を **cv2 import より前に** |
| **実部品で刻印の正方形の縁が黒い線で写る** | 刻印入りの別メッシュを面から 0.02mm 浮かせていた。**`check_patch_seam.py` は ISP 後のノイズ込み画像で測り「見えない（1.06）」と誤判定**。EXR で測ると縁の勾配は外側の 1.68 倍（最大 7.8） | **STEP の B-rep に直接刻印**（`prep_part.engrave_part`）。同じ視点で 0.96 倍 = 縁なし（2026-09-14） |
| **刻印の中心に放射状の星形ハイライト** | 異方性反射に Tangent を繋がないと、Cycles は**物体原点まわりの放射方向**を使う。原点＝刻印の中心 | 面内の一定方向を Tangent に繋ぐ（`render_scene.brush_tangent`）。**旧 ds_new の板金にも入っていた** |
| **刻印に軍手・工具がかぶる（遮蔽なしの前提が破れる）** | 遮蔽判定がマークごと 3×3 点の光線だけで、**点の間を物が覆うと素通り**。レンズ直前の軍手で全面黒のコマも `unoccluded=1.0` | **物の全頂点を投影**して刻印ブロックの矩形に入るかで判定（`movers_over_block`）。**サンプルシートを必ず目で見る**（数値では出ない） |
| **Blender のレンダが CPU 律速（遅い CPU の機体）** | 毎フレーム、浮動小数テクスチャ・大きなメッシュを Cycles へ送り直す | `render.use_persistent_data = True`（4.17 → 2.19 秒/枚、画像は同一）。GPU は CUDA と OPTIX の**片方だけ**有効に |
| **継ぎ目・段差の検査で見逃す** | ノイズ・トーン処理後の 8bit で勾配を測ると、ノイズの勾配が支配して差が消える | **リニア EXR で**、縁の細い帯と少し外の帯を比べる |
