## 1. プロジェクト概要

### 1.1 目的

工業部品の写真（スマートフォン、静止画 1 枚）から、部品に入った**刻印（材料表示・ロゴ・文字列）のまとまり全体**を
**画像の縦横に沿った矩形（Bbox）**で囲み、その部分だけを切り出す。
切り出した画像は後段（文字認識など、本システムの対象外）に渡す。

### 1.2 入出力

| | 内容 |
|---|---|
| 入力 | 8bit 画像 1 枚（学習と評価は 1024×768、グレースケールで使う） |
| 出力 | 刻印ブロックの軸平行 Bbox (x0, y0, x1, y1)［画素］ |

### 1.3 合格基準（評価の定義）

1 コマの予測 Bbox が次の 2 つを**両方**満たせば合格。

1. **教師 Bbox を 100% 覆う**（被膜率 100%）
2. **面積が教師 Bbox の 2.0 倍未満**

教師 Bbox の定義は §3.3。損失の面積目標は 1.5 倍（§5.1）で、評価上限 2.0 倍との差を余裕にしている。

### 1.4 対象（4 材質 + 実部品）

| 材質 | 刻印の見え方 | 難しさ |
|---|---|---|
| ガラス | 白セラミックの焼き付け（Honda ロゴ・英字行・丸囲み文字）。黒フリットのドット列が競合 | 映り込み（蛍光灯・電球・窓） |
| 布タグ（シートベルト） | 黒い織ラベルに白の印字・ロゴ | 易しい。帯の畝と縫い目が競合 |
| 実部品（STEP） | 金属面の絞り刻印（凹凸 0.125〜0.175mm）。材質コード数行 + 大きな 1 文字 | 金属の鏡面反射、小さく写る、影 |
| 吸音材（フェルト） | **深さ約 2mm の焼き印**（文字部分が黒ずむ） | 繊維の模様が強い |

### 1.5 制約（ユーザー要件）

| 項目 | 内容 |
|---|---|
| 速度 | 確率マップまで 50ms、最終 Bbox まで 150ms（スマホ） |
| 実写データ | 入手不可。**すべてデジタルツイン（合成）で開発・評価する** |
| 撮影側の施策 | 不可（フラッシュ・偏光・斜光誘導などは使えない） |
| 撮影条件 | 刻印部の法線から 45 度以内（吸音材は 20 度以内・画面占有 70〜90%） |
| 遮蔽 | **刻印を遮る物は無い前提**（影・手・工具は刻印に重ならない範囲で写る） |
| カメラ | 最新世代のスマホ相当。主な悪条件は手ブレとピンぼけ |
| 妥協する条件 | 蛍光灯などによる局所的な白飛び（物理的に判別不能） |

## 3. デジタルツイン（データ生成）

### 3.1 シーン組み立て

| 材質 | 実装 | 内容 |
|---|---|---|
| ガラス | `prep_scene.build_glass` | 着色ガラス + 白セラミックの刻印（ロゴ・英字行・丸囲み）+ 黒フリットのドット列。gen は本物の Honda ロゴ |
| 布タグ | `prep_scene.build_label` | 織りベルト + 黒ラベル + 白印字（織り目で分断）。gen は本物ロゴ |
| 吸音材 | `prep_scene.build_felt` | 繊維の起伏（1 本ずつ描く）+ くぼみ 1.5〜2.5mm（縁の丸み 0.2〜0.45mm）+ **焼き印**（文字の形に沿って 35〜55% 暗く、縁ににじみ、ムラ、文字上の繊維も焦げる）+ 熱圧で周囲の繊維を平す |
| 実部品 | `prep_part.py` | STEP の平面から刻印面を選び、**B-rep に直接刻印**（下記） |

**実部品の B-rep 直接刻印（`prep_part.engrave_part`）**

1. STEP を gmsh（OpenCASCADE）で読み、剛体変換で刻印面を z=0、面の u/v を X/Y にする
2. gmsh の Box 場で、刻印の正方形の中だけ高さマップの画素ピッチ（約 27µm）、外へ 6mm かけて 1.2mm まで粗くして部品全体を 1 枚のメッシュにする
3. 正方形の中の節点を高さマップで z 方向に動かす

別メッシュを重ねないので、継ぎ目や縁の影は出ない。刻印の文字高・行数は、回転後の外接が正方形の 88% に収まるよう逆算する。

**部品の分割**: 140 部品（3 組立）。gen は未見の組立 A0072601285 の 32 部品。残り 2 組立を train 96 / val 12 に重複なく分ける。

### 3.2 レンダリング（`blender/render_scene.py`、Blender 5.2 Cycles）

| 項目 | 内容 |
|---|---|
| 解像度・画質 | 1024×768、48 spp、OIDN デノイズ、16bit EXR（DWAA） |
| 照明 | 工場系 HDRI（train 0〜15、gen 16〜23 は未見）、直射光（なし/蛍光灯/電球）、影を落とす板 |
| 周辺物 | 実物の手・工具（CC0）。**刻印ブロックの画像上の矩形に 1 頂点でも入る物は遠ざけ、だめなら消す**（`movers_over_block`） |
| 視点 | 刻印法線まわりの格子: 傾き 0/11/22/33/44 度 × 方位 5 × ロール 0/120 度 = 最大 42 視点（吸音材は傾き 0/7/14/20 度で最大 32）。高さマップの地平線判定で読めない視点は撮らない |
| 画角 | 刻印ブロックの画面占有率（幅・高さの大きい方）を投影で合わせる。20〜70%（0.22/0.38/0.54/0.68）、吸音材は**教師 Bbox で** 70〜90%（0.72/0.80/0.88） |
| 金属 | 無地の金属材質。異方性の向きは面内の一定方向（原点まわりの放射にならないように） |
| 高速化 | `use_persistent_data`（フレーム間でシーンを送り直さない）、GPU は OptiX のみ有効 |
| 正解 | カメラ姿勢から正解ホモグラフィ H（平板 z=0 [m] → 画像画素）を記録 |

### 3.3 教師 Bbox

`ds.block_aabb`: 見えているマークの**刻まれた画素**（シーン npz の `ink > 0.5`）を H で画像へ射影し、その外接矩形を取る。
画面外にはみ出た分は画像の縁で切る。マークの mm 矩形の角を射影する方式は、傾いた刻印ほど箱が膨らむので使わない。

### 3.4 ISP 模擬（`ds.render_image`、学習時に毎回ランダム）

物理の順序で掛ける: ピンぼけ → 手ブレ → 露出（中央重点）→ センサノイズ → 多フレーム合成 → 局所トーンマップ → デノイズ → シャープ → sRGB → JPEG。

| 項目 | 範囲（`ISP_PROFILE = "modern"`） |
|---|---|
| 手ブレ | {0, 0, 1, 2, 3.5, 5.5} px @幅 512 → 1024px では 2 倍 |
| ピンぼけ | {0, 0, 0, 0.8, 1.6, 3.0} px @幅 512 → 1024px では 2 倍 |
| 感度 | 0.6〜1.5 |
| 多フレーム合成 | 2 枚以上（暗いほど多い） |
| デノイズ | 中央 0.10〜0.35、上限 0.5 |
| 局所トーンマップ | 0.15〜0.60 |
| JPEG 画質 | 82〜96 |
| デジタルズーム | 切り出し倍率に応じて実効画素まで解像度を落とす |

## 4. 認識モデル（v6H）

### 4.1 全体図（入力 1024×768 のときの形）

```
画像 8bit (768×1024)
  │ to_input: 輝度 / 局所コントラスト（窓 49px）
  ▼ x: 2×768×1024
MarkNet2（1024px 初段）
  s1: cbr(2→16) @1024 → cbr(16→32, stride 2) @512        ← 細い筆画を全画素で見てから間引く
  s2: 64ch @256   s4: 80ch @128   s8: 96ch @64   s16: 96ch @32   ctx: 拡張 d=4,8 @32
  top-down 融合 → f: 64×96×128（stride 8、受容野 約 950px）
  │
  ├─ seg (1×1)        → p = sigmoid       筆画らしさ            96×128
  ├─ VoteHead         → conf = sigmoid    マークの塊らしさ       96×128（ほかにオフセット・寸法・角度）
  └─ ExtentHead（拡張 d=2,4,8,16）
        blk  = sigmoid  ブロックの内側らしさ                    96×128
        ltrb            ブロックの 4 辺までの符号付き距離 [px]   4×96×128
  │
  ▼ 基準箱 = Σ blk·(各セルが指す辺) / Σ blk      （閾値なし）
BlockHead2（Transformer）
  [f, blk, 座標 x/W, y/H] → stride 2 ×2 → トークン 24×32 + CLS（基準箱を埋め込み）
  4 層・4 ヘッド・d=96 → 差分 (Δcx/w, Δcy/h, Δlog w, Δlog h)（0 初期化）
  ▼ 粗い箱
Refiner
  粗い箱の 1.5 倍を 96×96 で切り出し: 画像 2 面 + 地図 3 面（p, conf, blk）
  cbr×3 → 行方向・列方向に平均 → 1D 畳み込み → 4 辺の補正（tanh で上限）
  ▼ 最終の Bbox
```

### 4.2 各部の要点

| 部品 | 役割 | 設計の理由（経緯は docs/07） |
|---|---|---|
| 入力 2 面 | 輝度と局所コントラスト | 刻印は「周りに対するずれ」。窓は解像度に比例 |
| 1024px 初段 | 16ch を全画素で掛けてから stride 2 | 細い筆画の情報を落とさず、以降は 512px 入力と同じ計算量（§42.4） |
| ピラミッド（s8/s16/ctx） | 中域・大域の構造 | 「短い筆画の群れ」と「部品を貫く筋」を分けるため（§34） |
| ExtentHead | ブロックの外形を直接学習 | 筆画の証拠（p×conf）から箱を作ると、弱い端のマークで外形が途切れた（§39） |
| 基準箱 | blk 重み付きの辺の平均 | 閾値を使わない。勾配が外形の頭まで流れる |
| BlockHead2 | 基準箱の補正 | 全体を見た補正。位置は座標の面で渡す（学習する位置埋め込みは 1024px で足りなかった） |
| Refiner | 4 辺の精密化 | stride 8 の量子化を受けない。地図を足さないと、かすかな端のマークを「何も無い」と見て内側へ詰めた（§39） |

### 4.3 計算量（網全体、GMAC = 積和演算 10^9 回）

| 構成 | 確率マップまで | 最終 Bbox まで |
|---|---|---|
| 512px 入力（v5 まで） | 8.15 | 8.99 |
| 1024px・構造そのまま（参考） | 32.60 | 38.24 |
| **1024px 初段 16ch → stride 2（v6）** | **9.17** | **10.01** |

以前の見積もり（29.7 GMAC ≒ INT8 で 29ms）から比例させると、v6 は約 10ms 相当。スマホでの実測はまだ無い。

## 5. 学習（`tools/train_block2.py`）

### 5.1 損失

**合格条件そのものを損失にする**（`pass_loss`）。箱 (cx, cy, w, h) と教師 Bbox の 4 隅 q について

```
s_u = τ·logsumexp(|q_x − cx| / (w/2) / τ)    s_v = τ·logsumexp(|q_y − cy| / (h/2) / τ)    τ = 0.05
L_pass = λ·[ relu(log s_u − log S) + relu(log s_v − log S) ] + relu(log(w·h / 教師面積) − log A)
S = 0.95（内側に 5% の余裕）、A = 1.5（面積目標）、λ = 3
```

| 項 | 重み | 内容 |
|---|---|---|
| L_pass（最終の箱） | 1 | 上式 |
| L_pass（粗い箱） | 0.5 | 上式 |
| L_pass（基準箱） | 0.5 | 上式 |
| 外形 | 1 | blk の BCE（教師 = 教師 Bbox の内側）+ ltrb の smooth L1（64px で正規化、ブロック内 1.0・外 0.1 の重み） |
| 内詰めの罰 | 3 | 辺ごとに［粗い箱は覆えていた］×［最終の漏れ（教師の辺長比）］ |
| 補助（背骨を学習する期間） | 1 / 0.05 / 1 | 筆画の focal BCE（部品表面の負例 8 倍・構造 24 倍）/ 投票オフセットの L1 / conf の BCE（マーク矩形） |

### 5.2 手順とハイパーパラメータ

| 項目 | 値 |
|---|---|
| 初期値 | 背骨 `vote_P0_bb.pt`・投票頭 `vote_P0.pt`（512px で学習済み）から転移。1024px 初段・外形の頭・差分頭・Refiner は新規 |
| 段階 | 1〜3 エポック: 新規の部品と初段だけ学習（背骨は凍結、勾配は初段まで通す）→ 4 エポック以降: 背骨と投票頭も学習率 ×0.1 で |
| BN | 背骨は統計固定（eval）。新規の初段だけ統計を更新 |
| 最適化 | AdamW、学習率 5e-4、weight decay 1e-4、OneCycle（30 エポック）、勾配クリップ 1.0 |
| バッチ | 8 |
| エポック | 30（val の合格率は 17 エポック付近から横ばい） |
| モデル選択 | val 240 コマ（シーンごとに均等）の最終の箱の合格率が最良のエポック |
| データ読み | torch DataLoader（プロセス 48、使い回し）。乱数はコマ番号とエポックで決まる |
| 実行環境（v6） | vast.ai 4×RTX 4090（学習は 1 枚）/ 96 スレッド。1 エポック 130〜160 秒、30 エポック約 75 分 |

## 6. 評価

### 6.1 指標

| 指標 | 定義 |
|---|---|
| 合格率 | §1.3 の条件を満たすコマの割合（材質別、段別: 基準箱 / 粗い箱 / 最終） |
| 被膜率 | 教師 Bbox の面積のうち予測 Bbox に入る割合 |
| 面積比 | 予測 Bbox の面積 ÷ 教師 Bbox の面積 |
| s* | 教師を覆うのに必要な箱の倍率（軸ごと） |
| 明らかな未認識 X1 | 最終の箱の被膜率 < 90% |
| 可視度 | 刻印の輪郭の勾配 ÷ すぐ外の背景の勾配（1.0 = 区別できない） |
| 吸音材の自明解 | 画像全体を Bbox にしたときの合格率（画面占有 70〜90% のため、比較用） |

### 6.2 結果（v6、全コマ）

| 材質 | gen | val |
|---|---|---|
| ガラス | 98.2% | 97.4% |
| 布タグ | 99.7% | 99.2% |
| 実部品 | 97.6% | 96.7% |
| 吸音材 | 94.9%（自明解 28.1%） | 91.3%（自明解 28.3%） |
| **全体** | **97.8%** | **96.8%** |
| 参考: 面積 < 1.5 倍 | 91.1% | 87.7% |

### 6.3 版ごとの変遷（gen 全体の合格率）

| 版 | 主な変更 | gen 合格率 |
|---|---|---|
| v4 | 512px、基準箱 = p×conf のモーメント、面積目標 1.3 → 1.5 | 85.2% |
| v5 | 外形の頭、Refiner に地図と内詰めの罰 | 91.0% |
| **v6** | **1024px 入力（初段 16ch → stride 2）、吸音材の焼き印、最新カメラ相当の ISP** | **97.8%** |

v6 は 3 つを同時に変えたので、それぞれの寄与は切り分けていない。

### 6.4 残る失敗（gen+val 2,931 コマ中 不合格 75、X1 17）

| 種類 | 例 | 状況 |
|---|---|---|
| (a) 映り込みで刻印が白く飛ぶ | ガラスの蛍光灯・電球の反射 | 物理的に判別不能な部分がある（妥協条件） |
| (b) 小さく写った・影やハイライトの中の刻印 | 実部品、画面占有率 < 0.30 で不合格 4.2% | |
| (c) 画面いっぱいで強い手ブレ | 吸音材 | |
| (d) 行から離れた大きな 1 文字・ロゴ | 実部品 p9202 007 など | Bbox からはぐれる |

実部品で覆えなかった 19 件のうち、被膜率 ≥ 99% は 4 件、≥ 95% は 10 件。1 段目が刻印を丸ごと見失った例は 0。

## 7. 推論（`tools/infer_block.py`）

```
python tools/infer_block.py --model v6H.pt --image photo.jpg --vis out.png
```

- 入力は任意の 8bit 画像。4:3 に黒で埋めてから 1024×768 に縮め、出力は元画像の画素座標に戻す
- 出力 JSON: `bbox`（最終）, `base`, `coarse`, `time_ms`
- モデルファイル 1 つで動く（元の背骨の重みは不要）
- 自己検証: `python tools/infer_block.py --model v6H.pt --selftest <ds_v4>`

## 8. 再現手順

### 8.1 環境

| 項目 | 版 |
|---|---|
| Python | 3.11〜3.13 |
| PyTorch | 2.4 以上（CUDA。Intel GPU は XPU 版、要コード対応） |
| OpenCV | **4.10.0.84 に固定**（5 系は EXR を読めない） |
| その他 | numpy, scipy, Pillow, gmsh（実部品のシーン作成のみ） |
| Blender | 5.2.1（データ生成のみ） |
| 環境変数 | `OPENCV_IO_ENABLE_OPENEXR=1`（cv2 の import より前）、Windows では `KMP_DUPLICATE_LIB_OK=TRUE` |

### 8.2 データ生成

```
# STEP の場所（既定は C:\Users\hide2\IdeaBox\PartMaker\fill_mid_surf）
set STEP_ROOT=<fill_mid_surf のパス>
set ROLLS=0,120
python tools/make_dataset.py --root out/ds_v4 --mult 3 --res 1024 --samples 48 --workers 4
#   GPU ごとに分けるとき: CUDA_VISIBLE_DEVICES=i ... --shard i/N
python tools/verify_dataset.py --root out/ds_v4 --sample 300
python tools/sample_sheet.py --dirs out/ds_v4/train/p9100 --out out/sheets
```

Blender のパスは `tools/make_dataset.py` の `BLENDER`。所要（4×RTX 4090）: レンダ約 1.3 時間。

### 8.3 学習

```
python tools/train_block2.py --root out/ds_v4 --stem hires --refine 1 --ft 1 --warm 3 --epochs 30 --lam 3 \
    --n-val 240 --workers 16 --procs 48 --extent 1 --inward 3 --area-tgt 1.5 --area-max 2.0 --out out/v6H.pt
```

`--procs` はデータ読みのプロセス数（CPU コアに合わせる）。背骨の初期値 `out/vote_P0_bb.pt` と `out/vote_P0.pt` が必要。

### 8.4 評価と分析

```
python tools/viz_block2.py --root out/ds_v4 --ckpt out/v6H.pt --split gen --scan 2000 --out out/v6_eval --dump out/v6_rows_gen.json
python tools/analyze_stage1.py --root out/ds_v4 --ckpt out/v6H.pt --splits gen,val --case p --out out/v6_stage1
python tools/analyze_fail.py --root out/ds_v4 --ckpt out/v6H.pt --splits gen,val --out out/v6_fail
```
